# Regenerating every figure, table and number

Run from the repo root with the package installed (`pip install -e .`).
Paths assume the paper lives in `Fcom__Atlas_Autoencoders/`, a local directory
that is deliberately untracked: the LaTeX sources are not part of this
repository, so the steps that copy figures into it are no-ops for anyone who
does not have it. Everything else here runs from a fresh clone.

Total wall time on a laptop CPU: roughly **6–9 hours**, dominated by the
cyclo-octane and patch experiments. The two cheap steps (§0) take under a minute
and are the ones to run if you only want the tables refreshed.

---

## Trained atlases are now saved

Every driver writes its trained networks to `<results_dir>/atlases/`, and
`atlasae.load_atlas` reloads them exactly (verified bit-identical). A full set
for the paper is under 2 MB.

```python
from atlasae import load_atlas
system = load_atlas("experiments/results/results_paper_.../atlases/S2_seed42")
```

This exists because every diagnostic added after the fact — the explicit
threshold Θ, the latent gauge, volume regularity, sign constancy — needed the
networks rather than the recorded scalars, and so cost a full retrain each time.
Runs made before 2026-08-04 have no `atlases/` directory; anything requiring the
networks must be recomputed from a run made after that date.

**Add `experiments/**/atlases/` to `.gitignore`** if you would rather not commit
them, but keep them locally.

## Full re-run: just use `run_all.sh`

```bash
./run_all.sh --quick     # ~15 min, tiny budgets: checks every stage works
./run_all.sh             # the real thing, ~6-9 h
```

It runs all fourteen stages in sequence, logs each to `logs/<stage>.log`, and
prints the three table bodies at the end. Useful flags:

| flag | effect |
|---|---|
| `--quick` | tiny budgets end to end; run this first |
| `--resume` | skip stages that already finished |
| `--only s2,klein` | run a subset (`--list` shows the names) |
| `--seeds N` | override the seed count |
| `--mat`, `--images` | data paths (both default to the copies in the repo) |

A stage that fails is reported and the run continues, so one breakage doesn't
cost the whole night; the script exits non-zero if anything failed. Result
directories are timestamped, so **nothing is overwritten** — earlier runs stay
put and the new ones land alongside. Compare before adopting either:

```bash
cd experiments && python make_master_table.py            # newest
python make_master_table.py --strict                     # newest complete
```

The sections below document the individual commands, for when you want to run
one stage by hand.

## 0. Cheap — no training, run these first

These read the recorded runs and rebuild everything derived from them.

> **Do not rebuild tables while an experiment is still running.** The scripts
> pick the *most recent* results file, and a run in progress writes
> incrementally, so a partly-finished experiment would silently shrink its row
> and the totals. `make_master_table.py` warns when a run has fewer than five
> trials; pass `--strict` to fall back to the newest *complete* run instead.
> Warnings go to stderr, so `--latex 2>/dev/null` stays paste-clean.

```bash
cd experiments

# main-text summary table (tab:summary_all)
python make_master_table.py --summary

# supplement master table (tab:master)
python make_master_table.py --latex

# supplement Theta table (tab:theta)
python E5_theta/theta_certificate.py --latex

# eta_pca validation figure (Figure SM8) + its statistics
python E1_eta_codim/eta_validation.py \
    --fig ../Fcom__Atlas_Autoencoders/eta_fig/eta_validation.png --latex

# RP2 embedding figure (Figure 3)
python make_rp2_embedding_fig.py \
    --out ../Fcom__Atlas_Autoencoders/cyclo_fig/rp2_embedding.png
```

Paste the three table bodies over the block marked
`% generated by ... -- do not edit by hand` in `main.tex` / `supplement.tex`.

The last line writes `RP2_raw.json`; without `--raw-patches` you get the

(see §4.4 of the paper).

> takes the first `--max-images` files in sorted order and records the selection
> under `image_selection` in the results. **Any van Hateren numbers produced

> should be the one whose `image_selection` is recorded.

## 4b. Reconstruction-error floor on real patches (supports a claim now unbacked)

The paper reads the large $\varepsilon$ on van Hateren patches as an intrinsic
thickness of the cloud rather than undertraining, and says it is "stable across
cover size, chart count, epochs and sample size". **No run on disk tests that.**
This sweep does, varying one axis at a time, with the analytic model as a
positive control (it should improve with budget, being an exact manifold).

```bash
cd experiments/E4_real_data
python eps_floor_sweep.py --images /path/to/vanhateren_iml --seeds 3  # ~3 h
python eps_floor_sweep.py --synthetic --seeds 3                       # control, ~1 h
python eps_floor_sweep.py --synthetic --quick                         # 10-min check
```

Flat $\varepsilon$ across all three axes supports the claim; a fall with epochs
or sample size means it should be removed.

## 5. Latent gauge fixing — done, and it does *not* close the gap

```bash
cd experiments
python E6_gauge/run_gauge.py --manifolds S2 Mobius RP2 --seeds 42 43 44 45 46
```

Result (feeds `tab:gauge`): the optimal rescaling raises $\delta$ by 1.0–3.9× and
attains the theoretical ceiling exactly, but the ceiling itself is only 0.13
($S^2$), 0.50 (Möbius), 0.09 ($\mathbb{R}P^2$), so $\Theta<\delta$ still fails.

**Why, and what to try next.** The ceiling is exactly

$$\text{ceiling}=\min_{i,j}\sqrt{\inf_x|\det g_{ji}(x)|\,/\,\sup_x|\det g_{ji}(x)|},$$

i.e. it is set by how much $|\det g_{ji}|$ varies *within a single overlap* —
something no rescaling can touch. The measured ceilings imply $|\det g|$ spans
roughly 57×, 4× and 132× across some overlap on the three manifolds.

## 5b. Volume regularisation — tried, does **not** work

> **Result (2026-08-04): the intervention makes the target metric worse.**
> Matched pair on $S^2$, 800 epochs, seed 42:
>
> | `lambda_vol` | $\varepsilon$ | $\eta$ | ceiling |
> |---|---|---|---|
> | 0    | 0.062 | 0.452 | **0.122** |
> | 0.1  | 0.130 | 0.862 | **0.010** |
>
> The ceiling — the quantity the term was designed to raise — falls by a factor
> of twelve, and $\varepsilon$ and $\eta$ roughly double. The likely mechanism:
> the argument that uniform $|\det dE_i|$ gives constant $\det g_{ji}$ relies on
> $dD_i\approx(dE_i)^{-1}$, which only holds once reconstruction has converged.
> Engaging the term early instead fights the primary objective and leaves the
> atlas in a worse configuration on every axis.
>
> Before spending more time here: a warmup variant (converge $\varepsilon$ first,
> then engage, as `diff_warmup` does) is the one remaining variant worth a run,
> but the direction of this result is discouraging and **the paper does not
> depend on it** — the $\Theta$ gap is already documented honestly as open in
> `app:theta-gap`. Recorded so the route is not re-tried blind.

### Original rationale

If each encoder distorts volume *uniformly* over its chart, then
$\det g_{ji}=\det(dE_j)\det(dD_i)$ is nearly constant on overlaps, the ceiling
rises toward 1, and (with $\eta<0.14$, already reached on the best charts)
$\Theta<\delta$ comes into range for the first time. `fast_fit` now takes
`lambda_vol`, penalising the variance of $\log|\det dE_i|$ over each chart.

**Always include `--lambda-vol 0` — it is the control.** A run at a single
non-zero weight cannot be interpreted, because the comparison is against the
same architecture and epoch budget with the term switched off, not against the
fully-trained baseline elsewhere in the paper.

```bash
cd experiments
# minimum interpretable check: matched pair at equal budget, ~30 min
python E6_gauge/run_volreg.py --manifolds S2 --lambda-vol 0 0.1 --epochs 800

# full sweep at the paper's budget
python E6_gauge/run_volreg.py --manifolds S2 Mobius RP2 \
       --lambda-vol 0 0.01 0.1 1.0 --seeds 42 43 44
```

Read the output as: **ceiling should rise with `lambda_vol`** relative to the
`lambda_vol 0` row at the *same* epoch count, while $\varepsilon$ and $\eta$ must
not degrade in exchange. If the ceiling climbs past $\Theta_{\rm LB}$ the
certificate becomes verified rather than calibrated, which is the open problem
named in the conclusions.

If the term slows reconstruction too much, the natural next variant is a warmup
(let $\varepsilon$ converge first, then engage the volume term), exactly as
`diff_warmup` does for the differential loss. Untested beyond a smoke run.

## 5c. Sign constancy from sampling density (replacement for $\Theta<\delta$)

The pipeline already verifies the cocycle identity **directly**, by autodiff, at
every sampled point (`verify_cocycle_condition`); that check is what produces the
"undetermined" verdicts, and on cyclo-octane it passes 20/20 where the
certificate passes only 16/20. The one thing $\Theta<\delta$ adds is coverage
*between* samples.

A covering argument buys that far more cheaply. In the latent coordinate,
with $f(z)=\det g_{ji}$, local spacing $h_k$ and local gradient bound $L_k$:

$$|f(z_k)| > L_k h_k \ \text{ for every sample } k \implies \operatorname{sign} f \text{ constant on the whole component.}$$

One measurable constant instead of four, no $(L_EL_D)^d$ amplification, and —
decisively — **the margin improves as you sample more densely** ($h\sim n^{-1/d}$),
which $\Theta<\delta$ never does.

```bash
cd experiments
python E7_signconstancy/run_signconstancy.py --manifold S2 --n 500 1000 2000 4000
python E7_signconstancy/run_signconstancy.py --manifold S2 Mobius Klein \
       --n 2000 --epochs 4000            # at the paper's training budget
```

Preliminary (S², 250 epochs only, so undertrained):

| n | median $h$ | median margin | certified |
|---|---|---|---|
| 500 | 0.088 | 0.019 | 0/12 |
| 2000 | 0.046 | 0.869 | 4/12 |

$h$ halved exactly as $n^{-1/2}$ predicts. Margins are not yet $>1$ everywhere,
but they are within reach — unlike $\Theta<\delta$, which fails by a factor of
at least 3–68 and cannot be improved by any amount of data. **Run at the paper's
4000-epoch budget before drawing conclusions**: the numbers above are dominated
by undertraining, not by density.
